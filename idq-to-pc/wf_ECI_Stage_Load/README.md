# wf_ECI_Stage_Load &rarr; IDMC CDI (importable)

`docs/wf_ECI_Stage_Load.xml` is an IDQ (Developer / Model Repository) export, which IDMC cannot import. This folder
holds the same workflow as a **PowerCenter repository export (POWERMART XML)**, which IDMC converts into CDI assets
through its PowerCenter migration path. Generated by `ext-tools/idq_to_pc.py`: regenerate it, don't edit it.

```sh
python -I ext-tools/idq_to_pc.py docs/wf_ECI_Stage_Load.xml idq-to-cdi
```

## Files

| File | Contents | Use |
|---|---|---|
| `wf_ECI_Stage_Load.XML` | Folder `ECI`: 7 source and 14 target definitions, 11 mapplets, 9 mappings, 9 sessions, workflow `wf_ECI_Stage_Load` | Upload to the IDMC PowerCenter migration / conversion: it becomes 9 mappings, 9 mapping tasks and one taskflow |
| `mapplets/*.XML` | Each mapplet on its own | Optional: CDI *New > Mapplet - PowerCenter* upload when you need a single mapplet |
| `wf_ECI_Stage_Load.param` | PowerCenter parameter file with the IDQ parameter defaults, one section per session | Carry the values into the mapping-task parameters or a CDI parameter file |
| `conversion_report.md` | Every translation that is not one to one, per object, and the *Filtered data* chapter (which rows each mapping drops or diverts, and which never reach a `C_S_*` table) | Review list before go-live |

## Before you upload

1. **Connections**: create them in IDMC with the IDQ names, so the converted assets bind automatically:
   `HHS_MDM_ORS`, `INFA_STAGE`, `STAGING` (Oracle) and `Snowflake_PEI` (ODBC in IDQ; used by the lookup on
   `RDM.REF_PHN_AREA_CD`, so point it at Snowflake).
2. **Validate the XML first, if you can.** Nothing here has been through a PowerCenter or IDMC import yet. If a
   PowerCenter 10.x repository is available, import it there (Repository Manager *Import Objects*, or
   `pmrep objectimport`) and validate the mappings. Fix anything the importer reports, then upload the re-exported
   XML to IDMC.
3. Runtime: a Linux Secure Agent group. The command task runs
   `cd /opt/apps/informatica/SrcFiles/Indicators && touch wf_ECI_Stage_Load.ind` on the agent host.

## How the IDQ objects were translated

| IDQ | PowerCenter XML (then CDI) |
|---|---|
| Relational data object source + SQL override / filter | Source definition + Source Qualifier (*Sql Query*, *Source Filter* carried over) |
| Expression, Filter, Router, Lookup, Union, Update Strategy | Same transformation; expressions unchanged except `$Param` &rarr; `$$Param`, `$sys.MappingName` &rarr; `$PMMappingName`, `$sys.MappingRunStartTime` &rarr; `SESSSTARTTIME` |
| Mapplet in a mapping | Mapplet; output ports that share a name with an input port get an `o_` prefix (listed in the report) |
| Mapplet inside a mapplet | Inlined (PowerCenter does not allow nested mapplets): `<instance>_input` / `<instance>_output` pass-through Expressions |
| Case Converter | Expression with `UPPER` / `INITCAP` |
| Token Standardizer | Expression: one variable port per operation (`REPLACESTR`, start/end matches), then remove multiple spaces and trim |
| Labeler | Expression: character labels &rarr; `REG_REPLACE` per character set; token labels &rarr; `REG_MATCH` with the token-set regex |
| Address Validator | **Placeholder Expression**: see below |
| Mapping task | Session (date format, high precision, tracing, log name); the Update Strategy session runs *Data driven* with *Delete* on its target |
| Workflow with inclusive gateways | Workflow links: each session starts when all its predecessors succeed (same order as the IDQ gateways) |
| Stale MDM timeline fields (`VERSION_SEQ`, ranks, `PERIOD_REFERENCE_TIME`, `TIMELINE_ACTION`) | Not ported (13 fields, 9 links) |

## Manual work after import (also in `conversion_report.md`)

- **Address verification.** `mplt_Global_Addr_Validation.dq_Global_AddressValidation_Hybrid` is a placeholder. It
  echoes the input address lines, city, postcode and state, sets the country to `US` and leaves every status,
  mailability, CASS and geocode field NULL. Replace it with a CDQ Address Verifier (mode `CERTIFIED`, US) and map its
  53 linked ports. Until then `m_Tgt_C_S_ECI_Pty_Addr` treats every address as unverified.
- **`ref_special_char_list`** (`rule_MEDICAID_ID_Std`) is not in the export, so it is approximated as "remove every
  character that is not a letter, digit or space". Replace it with a lookup once the table is available.
- **`ref_Valid_City`** became the unconnected lookup `lkp_ref_Valid_City` on `INFA_STAGE.ref_Valid_City133231612434`.
  It matches the whole city value, case-insensitively; IDQ matched token sequences.
- **Title case**: `INITCAP` also capitalises after punctuation (`O'Brien`), while IDQ split on spaces only.
- **SSN token label**: `REG_MATCH` checks the whole trimmed value; IDQ labelled each space-delimited token.
- **Test filter**: the source `Read_STG_ECI_D_CHILD_AND_FAMILY` in `m_Tgt_C_S_ECI_Pty` carries the IDQ filter
  `ID_CHILD IN ('0001252185', ...)`. It is ignored because the source has an SQL override, but remove it anyway.
- **Parameter file path**: the sessions point at `$PMRootDir/ParamFiles/wf_ECI_Stage_Load.param`; change it to the
  location your mapping tasks use.
